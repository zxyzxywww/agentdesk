# 业务任务演示卡：主题调研报告（面试现场 Demo）

> 目的：向面试官展示"解决一个业务任务"，而不是"我有 17 个工具"。
> 一句话输入 → Agent 自主规划 → 多工具调研 → 写文件交付 → 反思自检修正。
> 不改任何代码、不预置内容，纯靠 Agent 能力完成。

## 演示任务（复制进输入框即可）

```
请调研「医学影像 AI 去噪」方向的技术现状与临床落地趋势：先用 web_search 查至少 3 个不同来源，
再逐篇 fetch 关键页面核实，最后把结论写成一份带小标题、要点和引用来源的调研报告 report.md
（先查资料再动笔，完成后自查是否覆盖：主流方法、代表论文/产品、临床落地情况三个要点）
```

## 预期可观察到的 Agent 工作过程（对照讲解点）

| 阶段 | 界面能看到什么 | 讲给面试官听 |
|---|---|---|
| 1 规划 | 右侧计划面板出现 4~6 步计划 | Planner 把模糊任务拆成可执行步骤 |
| 2 调研 | 执行面板滚动 web_search / fetch_page | 模型自主选择工具、多来源交叉核实 |
| 3 动笔 | 出现 write_file 调用、产 report.md | 工具结果驱动写作，不凭空编造 |
| 4 自检 | **紫色「反思自检」徽标消息** | 产出后评审一轮：是否覆盖三要点、引用是否真实 |
| 5 修正（若有） | 反思指出问题 → 继续调工具补全 | rework 返工循环，直到评审通过才收尾 |
| 收尾 | 验收面板列出产出的 report.md | ToolResult.files 驱动验收，可点击查看 |

## 若想演示"失败恢复 / 人工确认"
- 提一个会触发覆盖的任务（如"重写 report.md 补充结论"）→ 界面出现**确认弹窗**，讲解 HITL：危险操作必须先过用户这一关，批准后才继续。
- 故意在网络不可用时提调研任务 → 观察工具失败后模型换策略（失败恢复），不会中断。

## 面试讲解话术（收尾 30 秒）
> "您看到它完成了一次完整的业务闭环：接到任务先拆计划，用检索+抓取多来源核实信息，写文件交付，交付前还以评审者视角自检了一轮——发现问题会自己返工补全，而不是汇报'我觉得完成了'。整个过程每一步都有记录可回看、成本可核算、危险操作需要人确认。"
