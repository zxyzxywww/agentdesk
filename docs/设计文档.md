# AgentDesk 设计文档

## 1. 定位

通用任务型 Agent：用户用自然语言下达任务，Agent 自主规划（Planner）→
执行循环（ReAct）→ 调用工具 → 结果回填 → 护栏检查 → 任务验收。

## 2. 核心设计决策

### 2.1 为什么 ReAct 而非完整 Plan-Execute 框架？
- ReAct 循环里 LLM 每轮自选工具，天然支持 plan→act→observe 重规划，
  对"文件/数据处理"这类结果反馈明确的场景足够且简单；
- 额外加了一层**初始计划**（Planner）：不约束执行，只给用户可见的任务结构，
  并帮助 LLM 保持任务主线（计划随对话回填给模型）。

### 2.2 工具注册表为什么用 Pydantic 参数模型？
- 参数模型自动生成 JSON Schema（供 LLM 生成参数）+ 自动校验（防参数幻觉）；
- 执行入口统一（`ToolRegistry.execute`），工具只关注业务逻辑；
- 危险工具声明 `risky=True`，执行时通过 `ToolContext.confirmed` 决定是否放行。

### 2.3 危险操作确认机制
- 工具执行中若需确认抛 `NeedsConfirmation(reason)`；
- 引擎捕获后：任务状态置 `waiting_confirm`、DB 记录工具调用为待确认、
  发 `needs_confirm` 事件给前端弹窗；
- 用户「确认」→ `runner.confirm(call_id)`：以 `confirmed=True` **重跑原调用**
  （复用原 DB 记录，不产生重复）；「拒绝」→ `runner.reject(call_id)`：
  记录失败并提示模型调整方案后继续。

### 2.4 自动备份与撤销回滚
- 覆盖/删除/移动覆盖/合并输出前，`ToolContext.backup()` 把原始内容复制到
  `data/backups/`（workspace 之外，对工具不可见，防误删），并记录到 DB；
- `BackupManager.restore(backup_id)` 一键还原，恢复后标记 `restored`；
- 备份区与工作目录同级隔离，测试验证互不包含。

### 2.5 路径安全
`resolve_in_workspace`：相对路径基于工作目录解析，绝对路径必须位于工作目录内，
`resolve()` 展开 `..` 与符号链接后校验，越界抛错。上传接口只取 `basename` 防穿越。

### 2.6 搜索 provider 抽象
- `SearchProvider` 协议 + Tavily（API，免费额度）+ Fallback（DuckDuckGo/Bing HTML 解析）；
- `get_search_provider`：Tavily 缺 key 自动回退，离线测试通过注入 `httpx.Client`
  （MockTransport）完成，不依赖真实网络。

### 2.7 实时状态流
- 引擎与 UI 解耦：`AgentRunner` 通过 `on_event` 回调发 `AgentEvent`；
- FastAPI 侧把事件投递到事件循环（`run_coroutine_threadsafe`），经 WebSocket
  `/ws/tasks/{task_id}` 推给前端；前端按事件类型渲染工具卡片/计划/确认弹窗/验收。

### 2.8 成本控制
- `LLMClient` 累计 token 与成本（按模型价格表估算）；
- 护栏在每轮循环前检查：步数/成本/重复动作/取消，任一超限即终止（`stopped`）。

## 3. 数据流

```
用户指令
  → POST /api/sessions/{id}/tasks（FastAPI 创建任务，后台线程启动 AgentRunner）
  → Planner.plan（LLM 生成步骤计划，存 task.plan_json，发 plan 事件）
  → ReAct 循环：
      LLM.chat(messages + tools schema)
        ├─ 无 tool_calls → 最终答复 → _finish(done)
        └─ 有 tool_calls → 逐个：
             参数校验(ValidationError → 错误回填，不中断)
             → 执行工具(NeedsConfirmation → 挂起等确认/拒绝)
             → 结果摘要回填(截断 max_tool_output_chars)
             → 护栏检查(超限 → stopped)
  → _finish：写验收数据（summary/steps/cost/files）、存 assistant 消息、发 done 事件
  → 前端验收面板展示产出清单 + 用户确认
```

## 4. 存储设计（SQLite）

| 表 | 用途 |
|---|---|
| sessions | 会话（标题/工作目录/时间） |
| messages | 会话消息（用户指令/Agent 总结，UI 与引擎共同写入） |
| tasks | 任务（请求/状态/计划/摘要/步数/成本） |
| tool_calls | 工具调用记录（参数/结果/状态/耗时），结果截断存储 |
| backups | 备份记录（op/源路径/备份路径/是否已恢复），级联删除 |

## 5. 扩展点

- 新工具：定义 Pydantic 参数模型 + `Tool` 注册进 `build_default_tools()`；
- 新模型：`config.yaml` 改 `model.chat_model`，价格表 `MODEL_PRICES`；
- 新搜索源：实现 `SearchProvider`；
- 消息持久化与上下文裁剪：`MAX_HISTORY_MESSAGES`（默认 40 条）。
